# Butterfly Text-to-Image Retrieval

Enter a natural-language description of a butterfly and get back the most
relevant **existing** image from the dataset, ranked by CLIP cosine similarity.
This is retrieval, not generation: nothing is synthesized, and the source
dataset is never modified.


## 1. The dataset in this repository

Read from disk, never written:

| Source | Contents |
|---|---|
| `training_image/` | 1200 JPG files, `Image_1.jpg` … `Image_1200.jpg` |
| `Caption_blip.txt` | 1200 blocks of 5 numbered captions (6000 caption strings) |
| `Training_set.csv` | 6499 `filename,label` rows; the 1200 captioned images map to 75 species |

Generated by this project (safe to delete and rebuild):

| Artefact | Purpose |
|---|---|
| `data/descriptions.csv` | combined long-format dataset: one row per caption |
| `data/splits.json` | species-stratified, image-level train/val/test split |
| `data/dataset_report.{md,json}` | validation report for the sources |
| `embeddings/` | precomputed image embeddings + FAISS index + cache metadata |
| `models/` | fine-tuned checkpoints (only created by `train.py`) |
| `reports/` | evaluation reports |
| `outputs/retrieval/` | saved result plots and the last query JSON |

### `data/descriptions.csv`

| Column | Example |
|---|---|
| `filename` | `Image_1.jpg` |
| `label` | `SOUTHERN DOGFACE` |
| `caption` | `a yellow butterfly rests on a small flower` |
| `sentence_id` | `Image_1_c2` |
| `source` | `blip` |

One row per caption, so 6000 rows for 1200 images. Captions are copied
verbatim from `Caption_blip.txt` (only the `1. ` numbering prefix is removed);
1200 of them begin with a templated `"A photo of a <SPECIES> butterfly."`
sentence, which is preserved as-is. The combined CSV covers the captioned
range `Image_1` … `Image_1200` (`--max-index`); the other rows of
`Training_set.csv` describe images that are not part of this dataset.

## 2. Setup

```bash
python -m venv .venv

# NVIDIA GPU (recommended; swap cu126 for cu132 or cpu as needed)
.venv/Scripts/python -m pip install torch==2.14.1 torchvision==0.29.1 \
  --index-url https://download.pytorch.org/whl/cu126

# everything else
.venv/Scripts/python -m pip install -r requirements.txt

# on Linux/macOS use .venv/bin/python instead of .venv/Scripts/python
```

`requirements.txt` also carries the CUDA index as `--extra-index-url`, so a
plain `pip install -r requirements.txt` resolves the same versions.

Run the scripts from the repository root, e.g. `python src/search.py`. They
import each other by module name, so `src/` must stay the entry-point folder.

## 3. Commands

```bash
# 1. build the combined CSV, splits and the validation report
python src/build_dataset.py

# 2. precompute image embeddings (GPU, cached)
python src/encode_images.py

# 3. measure retrieval quality
python src/evaluate.py --split test --tag baseline

# 4. ask for images
python src/search.py
python src/search.py --query "orange and black butterfly on a purple flower" --topk 10
```

Further flags:

```bash
python src/build_dataset.py --max-index 1200        # limit which captions are combined
python src/encode_images.py --force --no-faiss      # rebuild cache without FAISS
python src/evaluate.py --split val --tag eval_val    # one split
python src/evaluate.py --split all --tag eval_all    # every image in one pool
python src/evaluate.py --compare reports/eval_baseline.json
python src/search.py --no-display --save            # headless, write a PNG
python src/search.py --auto-encode                  # encode on the fly if cache is missing
python src/train.py --epochs 5 --tune projection    # optional fine-tuning
```

Dataset location is configurable for Colab or a different folder:

```bash
python src/search.py --data-dir /content/butterfly-dataset
export BF_DATA_DIR=/content/butterfly-dataset   # same thing, via environment
```

## 4. How it works

* **Model** - `openai/clip-vit-base-patch32` via Transformers 5.x
  (`CLIPModel` + `AutoProcessor`). In v5 the feature helper methods return a
  `BaseModelOutputWithPooling`, so `src/model.py` reads `.pooler_output` and
  L2-normalizes it; dot product then equals cosine similarity.
* **Embeddings** - `src/encode_images.py` writes
  `embeddings/image_embeds.npy` (`float32`, `N x 512`), `filenames.json`
  (filenames + species labels), and `meta.json`, which records a fingerprint
  over the image set (name, size, mtime) plus the model id. The cache is
  reused while that fingerprint matches, so embeddings are recomputed only
  when the dataset or the model changes.
* **Retrieval** - `src/retrieval.py` ranks with FAISS `IndexFlatIP` when
  `faiss-cpu` and `embeddings/index.faiss` are present, otherwise with a NumPy
  matmul over the cached matrix. `--no-faiss` forces the NumPy path.
* **Splits** - by *image*, species-stratified, 80/10/10, seed 42
  (`data/splits.json`). All five captions of an image stay in one split, so no
  caption can leak between train and test.
* **Device** - CUDA when available, CPU otherwise; batch size defaults to 32
  on GPU and 8 on CPU to stay inside a 4 GB laptop GPU.

## 5. Evaluation metrics

`python src/evaluate.py` reports Recall@1/5/10 for two directions and two
relevance definitions:

* **exact** - the retrieved image must be the exact source image.
* **species-aware** - any image of the correct species counts as relevant.
  This is the headline metric: with 75 species over 1200 images, many images
  are equally valid answers for "a Monarch on a flower", and 470 caption
  strings repeat across images.

Pretrained CLIP ViT-B/32 without fine-tuning (`reports/eval_baseline.json`,
`reports/eval_baseline_val.json`):

| Split | text->image exact R@1 / R@5 / R@10 | text->image species R@1 / R@5 / R@10 |
|---|---|---|
| test (106 images, 530 queries) | 0.202 / 0.455 / 0.606 | 0.236 / 0.507 / 0.647 |
| val (137 images, 685 queries) | 0.184 / 0.476 / 0.615 | 0.219 / 0.515 / 0.663 |

The reverse direction (image->text) is in the JSON too: exact R@1 0.311 and
0.329 on test and val, species top-1 accuracy 0.359 and 0.387.

Results land in `reports/eval_<tag>.md` and `.json`. Pass
`--compare reports/eval_baseline.json` to diff a fine-tuned run against the
pretrained baseline.

## 6. Optional fine-tuning

```bash
python src/train.py --epochs 5 --batch-size 32 --tune projection
python src/train.py --steps 20 --out models/smoke   # quick smoke test
```

* Adapts the pretrained checkpoint only (never trains from scratch).
* `--tune projection` (default) trains the two projection heads;
  `--tune last_block` adds the last transformer block of each tower;
  `--tune all` trains everything.
* Validation species Recall@k is measured **before** and **after**; the
  checkpoint is written to `models/` (with `butterfly_config.json` recording
  hyperparameters, dataset fingerprint and metrics) only if it improves on the
  pretrained baseline. `--force` saves regardless (the last epoch's weights).
* Verified by a 5-step smoke run: the checkpoint is written with
  `model.safetensors` + `butterfly_config.json`, reloads offline via
  `--checkpoint`, and only the two projection heads differ from the base
  checkpoint.
* Point the other scripts at a fine-tuned model with
  `--checkpoint models/clip-butterfly`. The checkpoint is part of the cache
  fingerprint, so vectors from two different models are never ranked against
  each other: `evaluate.py` notices the mismatch and re-encodes automatically
  (about 6 s), while `search.py` stops with an error unless you pass
  `--auto-encode`. The cache is shared, so switching back to the pretrained
  model needs `python src/encode_images.py` again.

## 8. Troubleshooting

| Symptom | Fix |
|---|---|
| `dataset artefacts missing: ...` | run `python src/build_dataset.py` |
| `no embeddings at ...` | run `python src/encode_images.py` (or `--auto-encode`) |
| `CUDA requested but unavailable` | the run falls back to CPU automatically |
| `OutOfMemoryError` on encode | lower `--batch-size` (e.g. `--batch-size 8`) |
| `embedding cache not usable for this model (...)` | the cached vectors were built by another model - rerun `python src/encode_images.py`, or add `--auto-encode` to `search.py` |
| captions of an image split apart | never edit `splits.json` by hand; rebuild with `build_dataset.py` |
| `NOT saving: fine-tuning did not beat ...` | the run did not beat the baseline - rerun with `--force` to keep it anyway |
